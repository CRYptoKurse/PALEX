# Лексическая спецификация MiniCompiler 

## 1. Общие сведения
Данный документ описывает лексическую структуру исходного языка MiniCompiler — упрощённого диалекта C. Спецификация определяет множество допустимых символов, правила формирования токенов и их формальное описание в нотации EBNF.

## 2. Кодировка и множество символов
- **Кодировка:** UTF-8. Лексер работает с последовательностью байт, интерпретируемой как Unicode, однако все ключевые слова, операторы и разделители состоят из символов ASCII.
- **Пробельные символы:** пробел (` `), горизонтальная табуляция (`\t`), перевод строки (`\n`), возврат каретки (`\r`). Комбинация `\r\n` обрабатывается как один переход на новую строку.
- **Допустимые символы в исходном коде:** любые символы Unicode, однако за пределами строковых литералов и комментариев наличие символов, не входящих в определённые ниже категории, считается ошибкой.

## 3. Лексическая грамматика (EBNF)
(* Вспомогательные определения *)
letter = "A"…"Z" | "a"…"z" ;
digit = "0"…"9" ;
underscore = "_" ;

(* Пробельные символы *)
whitespace = " " | "\t" | "\n" | "\r" ;

(* Комментарии – удаляются препроцессором )
single_comment = "//" , { any_character - ("\n"|"\r") } , ("\n"|"\r"|ε) ;
multi_comment = "/" , { any_character } , "*/" ;
comment = single_comment | multi_comment ;

(* Ключевые слова *)
keyword = "if" | "else" | "while" | "for"
| "int" | "float" | "bool" | "return"
| "true" | "false" | "void" | "struct"
| "fn" ;

(* Идентификаторы *)
identifier = ( letter | underscore ) , { letter | digit | underscore } ;

(* Числовые литералы *)
integer = digit , { digit } ;
float = digit , { digit } , "." , digit , { digit } ;

(* Строковые литералы (экранирование в Sprint 1 не поддерживается) *)
string = '"' , { any_character - '"' } , '"' ;

(* Булевы литералы – совпадают с ключевыми словами true/false *)

(* Операторы )
arithmetic_op = "+" | "-" | "" | "/" | "%" ;
relational_op = "==" | "!=" | "<" | "<=" | ">" | ">=" ;
logical_op = "&&" ;
assign_op = "=" ;

(* Разделители *)
delimiter = "(" | ")" | "{" | "}" | ";" | "," ;

(* Объединённое определение токена *)
token = keyword
| identifier
| integer
| float
| string
| arithmetic_op
| relational_op
| logical_op
| assign_op
| delimiter
| eof ;

(* Конец файла *)
eof = ε ;

text

## 4. Категории токенов и их описание

### 4.1. Ключевые слова
Ключевые слова являются зарезервированными идентификаторами и не могут использоваться для имён переменных или функций.

**Список ключевых слов:**  
`if`, `else`, `while`, `for`, `int`, `float`, `bool`, `return`, `true`, `false`, `void`, `struct`, `fn`.

### 4.2. Идентификаторы
Идентификаторы служат именами переменных, функций и пользовательских типов.  
- **Начальный символ:** буква латинского алфавита (A–Z, a–z) или знак подчёркивания (`_`).  
- **Последующие символы:** буквы, цифры (0–9) или знак подчёркивания.  
- **Максимальная длина:** 255 символов.  
- **Регистрозависимость:** `Var` и `var` – разные идентификаторы.

### 4.3. Литералы

#### 4.3.1. Целочисленные литералы
- Состоят из одной или более десятичных цифр.  
- Ведущие нули разрешены (например, `007` интерпретируется как десятичное 7).  
- Диапазон значений: от `-2³¹` до `2³¹-1` включительно (соответствует 32-битному знаковому целому). Выход за этот диапазон считается ошибкой.

#### 4.3.2. Литералы с плавающей точкой
- Обязательно содержат десятичную точку, до и после которой должна быть хотя бы одна цифра.  
- Примеры: `3.14`, `0.5`, `10.0`.  
- Научная нотация (e-форма) в Sprint 1 **не поддерживается**.

#### 4.3.3. Строковые литералы
- Последовательность символов, заключённая в двойные кавычки (`"`).  
- Строка не может содержать неэкранированный символ кавычки внутри.  
- Поддержка escape-последовательностей (`\n`, `\t` и т.п.) в Sprint 1 **не реализована**.  
- Допускаются многострочные строки (содержат переводы строки).

#### 4.3.4. Булевы литералы
- `true` и `false` – одновременно являются ключевыми словами и литералами. Лексер распознаёт их как токены типа `KW_TRUE` / `KW_FALSE` и сохраняет соответствующее логическое значение (`True`/`False`) в поле `literal`.

### 4.4. Операторы

| Категория      | Операторы                          | Тип токена          |
|----------------|------------------------------------|---------------------|
| Арифметические | `+` `-` `*` `/` `%`                | `OP_PLUS`, `OP_MINUS`, `OP_STAR`, `OP_SLASH`, `OP_PERCENT` |
| Сравнения      | `==` `!=` `<` `<=` `>` `>=`        | `OP_EQ`, `OP_NEQ`, `OP_LT`, `OP_LE`, `OP_GT`, `OP_GE` |
| Логические     | `&&`                               | `OP_AND`            |
| Присваивание   | `=`                                | `ASSIGN`            |

### 4.5. Разделители
- Круглые скобки: `(`, `)` – `LPAREN`, `RPAREN`.  
- Фигурные скобки: `{`, `}` – `LBRACE`, `RBRACE`.  
- Точка с запятой: `;` – `SEMICOLON`.  
- Запятая: `,` – `COMMA`.

### 4.6. Пробельные символы и комментарии
- Пробелы, табуляции и переводы строк **игнорируются** лексером, но используются для корректного вычисления позиций токенов.  
- **Однострочные комментарии:** начинаются с `//` и продолжаются до конца строки.  
- **Многострочные комментарии:** начинаются с `/*` и заканчиваются `*/`. Вложенные комментарии (например, `/* /* */ */`) в Sprint 1 **не поддерживаются**.  
- Комментарии удаляются на этапе препроцессинга, поэтому лексер их никогда не видит.

### 4.7. Конец файла
Специальный маркер `END_OF_FILE` сигнализирует об окончании входного потока. Его позиция соответствует позиции сразу после последнего обработанного символа.

## 5. Обработка ошибок
При обнаружении символа, не соответствующего ни одному из допустимых шаблонов, лексер:
- генерирует токен типа `ERROR` с лексемой, равной недопустимому символу;
- записывает сообщение об ошибке во внутренний список;
- пропускает этот символ и продолжает разбор со следующего.

Также фиксируются ошибки:
- слишком длинный идентификатор (>255 символов);
- целочисленный литерал вне допустимого диапазона;
- незакрытая строка (отсутствует закрывающая кавычка);
- незакрытый многострочный комментарий (выявляется препроцессором).

## 6. Примеры распознавания

| Исходный фрагмент | Токены (позиция, тип, лексема, literal) |
|-------------------|------------------------------------------|
| `int x = 42;`     | `1:1 KW_INT "int"`<br>`1:5 IDENTIFIER "x"`<br>`1:7 ASSIGN "="`<br>`1:9 INT_LITERAL "42" 42`<br>`1:11 SEMICOLON ";"` |
| `3.14`            | `1:1 FLOAT_LITERAL "3.14" 3.14` |
| `"hello"`         | `1:1 STRING_LITERAL "\"hello\"" "hello"` |
| `true`            | `1:1 KW_TRUE "true" True` |
| `@`               | `1:1 ERROR "@"` |

## 7. Примечания для реализации
- Лексер должен работать за один проход (линейное время O(n)).
- Позиции токенов индексируются с 1 (первая строка, первая колонка).
- Перевод строки может быть представлен как `\n` (Unix), `\r\n` (Windows) или `\r` (старые Mac). Во всех случаях счётчик строк увеличивается на 1.
- Для максимальной производительности рекомендуется минимизировать копирование исходного текста и использовать просмотр вперёд без возвратов.
