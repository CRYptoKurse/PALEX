# Спецификация языка – Лексическая структура

Документ описывает лексическую грамматику исходного языка для проекта MiniCompiler.  
Кодировка исходных файлов: **UTF-8**.

## 1. Лексическая грамматика (в форме EBNF)
буква = "A"…"Z" | "a"…"z" ;
цифра = "0"…"9" ;
подчёркивание = "_" ;

идентификатор = (буква | подчёркивание) { буква | цифра | подчёркивание } ;

целый_литерал = цифра { цифра } ;
вещ_литерал = цифра { цифра } "." цифра { цифра } ;
строк_литерал = '"' { символ } '"' ;
булев_литерал = "true" | "false" ;

ключевое_слово = "if" | "else" | "while" | "for"
| "int" | "float" | "bool" | "return"
| "true" | "false" | "void" | "struct"
| "fn" ;

оператор = "+" | "-" | "" | "/" | "%"
| "==" | "!=" | "<" | "<=" | ">" | ">="
| "&&" | "||" | "!"
| "=" | "+=" | "-=" | "=" | "/=" ;

разделитель = "(" | ")" | "{" | "}" | "[" | "]" | ";" | "," | ":" ;

пробельный = " " | "\t" | "\n" | "\r" ;

| "/" { символ } "/" ;

## 2. Токены

Сканер формирует следующие категории токенов:

- **Ключевые слова** – зарезервированные слова, перечисленные ниже.
- **Идентификаторы** – имена, определяемые пользователем, соответствующие правилу `идентификатор`.
- **Литералы** – целые, вещественные, строковые и булевы значения.
- **Операторы** – арифметические, отношения, логические и присваивания.
- **Разделители** – знаки пунктуации, структурирующие код.
- **Конец файла** – маркер окончания ввода.

## 3. Детальные правила

### 3.1 Ключевые слова
Точный список (регистрозависимый):
if else while for int float bool
return true false void struct fn

text

### 3.2 Идентификаторы
- Должны начинаться с буквы (`a`–`z`, `A`–`Z`) или подчёркивания (`_`).
- Последующие символы могут быть буквами, цифрами (`0`–`9`) или подчёркиваниями.
- Максимальная длина: **255 символов**.
- Регистрозависимы: `counter` и `Counter` различаются.

### 3.3 Литералы

#### Целые литералы
- Последовательность десятичных цифр.
- Диапазон: **−2³¹ … 2³¹−1** (т.е. –2147483648 … 2147483647).
- Запрещены ведущие нули (кроме самого числа `0`).

#### Вещественные литералы
- Десятичная точка с обязательными цифрами с обеих сторон.
- Примеры: `3.14`, `0.5`, `10.0`.

#### Строковые литералы
- Заключены в двойные кавычки (`"`).
- Могут содержать любые символы, кроме незаэкранированной двойной кавычки.
- Управляющие последовательности (escape-sequences) **необязательны** в первом спринте (если реализуются, то следуют соглашениям языка C: `\"`, `\\`, `\n` и т.д.).

#### Булевы литералы
- `true` и `false` (также являются ключевыми словами, но представляют литеральные значения).

### 3.4 Операторы и разделители

| Категория          | Символы                                      |
|--------------------|----------------------------------------------|
| Арифметические     | `+`  `-`  `*`  `/`  `%`                      |
| Отношения          | `==` `!=` `<` `<=` `>` `>=`                  |
| Логические         | `&&` `||` `!`                                |
| Присваивания       | `=`  `+=` `-=` `*=` `/=`                     |
| Разделители        | `(`  `)`  `{`  `}`  `[`  `]`  `;`  `,`  `:`  |

### 3.5 Пробельные символы и комментарии
- **Пробельные символы** (пробел, табуляция, перевод строки, возврат каретки) игнорируются, кроме как для разделения токенов.
- **Однострочные комментарии** начинаются с `//` и продолжаются до конца строки.
- **Многострочные комментарии** начинаются с `/*` и заканчиваются на `*/`. Вложенность не допускается.
- При препроцессировании комментарии заменяются одним пробелом, сохраняя нумерацию строк для сообщений об ошибках.

### 3.6 Набор символов
Исходный код должен быть в кодировке UTF‑8. Внутри строковых литералов и комментариев могут встречаться любые символы Unicode, но вне этих контекстов допустимы только описанные выше символы ASCII.

5. Ошибочные ситуации
Сканер обязан сообщать о:

Недопустимых символах (не входящих ни в одну категорию токенов).

Незакрытых строковых литералах или блочных комментариях.

Целочисленных литералах, выходящих за допустимый диапазон.

Некорректных числовых литералах (например, 12. или .5).

Идентификаторах длиннее 255 символов.

Все сообщения об ошибках должны содержать номер строки и столбца, где обнаружена проблема.
